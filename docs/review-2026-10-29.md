# Repository review and remediation — 29 October 2026

Reviewed commit: `7ee64c70a255fc7ea92aa16d09eec04a89eb8ca6` on `main`.

This review covered the source-host admission path, approved-project execution,
environment checks, public demo admission, first-party OAuth session handoff,
and their tests. It was a source review on a Windows host, not a live E2B,
Oracle VM, Railway, or Cloudflare security assessment.

## Findings and changes

| Finding | Impact before remediation | Change |
| --- | --- | --- |
| Unresolved manifest includes could pass the approved-project gate | A NumPy pin plus `-r hidden.txt` was admitted as an isolated change even though the included dependencies were unknown. | Reviews now carry parse-resolution limitations into eligibility; unresolved includes, constraints, markers, and conditional declarations block approved-project runs. |
| Environment lock was a two-line marker | Its digest established only a declared Python/NumPy pair, not the installed package set. | New images record a versioned lock containing the Python version and sorted `pip freeze --all` output. Before source transfer, workers compare that file with the live environment and verify its approved SHA-256. Admission rejects manifests declaring packages beyond this NumPy-only pilot. |
| Draft creation consumed the daily execution quota | Cheap unauthenticated drafts could exhaust the 200-run global quota without executing anything. | Drafts have separate outstanding limits. Daily execution quotas are charged when a same-day draft starts. |
| OAuth session API returned the seven-day cookie token | Browser JavaScript could read and replay the long-lived session despite the cookie's HttpOnly flag. | The session API now returns a five-minute, separately scoped workspace token. The browser renews it from its HttpOnly session cookie after an API 401. |
| Connected replay accepted PRs with other changed files | A fixed-kernel replay could be offered for a PR whose other code changes were not executed. | Replay admission now requires a complete diff containing exactly one in-place change to the selected NumPy manifest. |

## Migration and operating limits

The old E2B template IDs and lock digests in
[the historical pilot proof](pilot-e2b-template-proof.md) are **not valid** for
new approvals. Build new templates and create new approved profile versions.
Oracle images likewise need rebuilding. The build output supplies the new image
or template IDs and lock digests; do not manufacture a digest from a version
string. Existing approved profiles with old hashes should remain disabled until
revalidated against a new profile version.

The versioned lock proves the package inventory observed in the prepared image
at build and run time. It does not prove that the repository's full dependency
file was installed. Approved-project runs still use only the reviewed NumPy
templates and execute the base source snapshot in both environments. The
connected fixture replay still executes only the byte-identical curated kernel.
Neither path establishes a causal explanation for an arbitrary dependency graph
or a general scientific correctness verdict.

The public demo remains a single-process service. Starting many real jobs can
still exhaust its bounded daily capacity. The new draft cap is a storage guard,
not bot prevention. Production abuse control needs an edge rate limit or a
verified identity policy before raising public quotas. The browser still holds
a short-lived bearer token, so same-origin script execution remains sensitive;
removing the site's inline-script CSP allowance is separate hardening work.
